# core — 영상 처리

**파일 하나를 넣어 파일 하나를 받는다.** 서버도 S3 도 없이 돈다.

```python
from face_anonymizer import VideoAnonymizer
res = VideoAnonymizer().process("in.mp4", "out.mp4")
```

---

## 한 편이 처리되는 순서

```
입력 ──▶ ① 코덱 정규화 ──▶ ② 메타 확인 ──▶ ③ 1차: 검출
                                              │
                                              ▼
결과 ◀── ⑥ 인코딩·오디오 ◀── ⑤ 2차: 렌더 ◀── ④ 추적·보간
```

**한 번이 아니라 두 번 훑는다.** 검출 결과를 들고 다시 읽는다. 30분 1080p 를
메모리에 통째로 올릴 수 없어서고, 그래서 두 패스의 프레임 수가 어긋나면 박스가
엉뚱한 프레임에 찍힌다 — 그건 검사해서 실패시킨다.

### ① 코덱 정규화 — `ingest.py`

OpenCV 의 ffmpeg 빌드는 본체보다 코덱 지원이 좁다. **AV1 은 파일을 열기는
열면서 한 프레임도 못 뽑는다**(실측: OpenCV 4.13, `isOpened()=True`, 디코딩
0프레임).

그래서 코덱 이름으로 판단하지 않고 **실제로 한 프레임을 뽑아 본다.** 목록으로
관리하면 빌드마다 다르고 새 코덱이 나올 때마다 어긋난다. 못 뽑으면 ffmpeg 로
H.264 로 옮겨 담고 그 파일을 다음 단계에 넘긴다.

전사는 검출 **전**이라 화질이 떨어지면 검출률이 같이 떨어진다. 그래서 CRF 를
낮게(고화질) 잡는다 — 중간 산출물이라 용량이 커도 되고 끝나면 지운다.
긴 영상은 이것만 수십 초라 `-progress` 로 진행률을 보고한다.

### ② 메타 확인 — `pipeline.probe()`

프레임 수를 **비디오 스트림 길이 × fps** 로 센다. 패킷 수는 편집된 파일에서
어긋나고, 컨테이너 전체 길이는 오디오가 더 길면 과대 계산된다. `fps` 가 NaN 인
파일도 있어서(`fps or 30.0` 으로는 NaN 이 통과한다) 정규화해서 받는다.

### ③ 1차: 검출 — `detector.py`

프레임을 배치로 읽어 넘기고 **프레임은 버린다.** 박스만 남긴다.

한 배치가 검출기를 지나는 과정:

1. **letterbox** — 원본 비율을 유지한 채 정사각 캔버스에 얹고 남는 곳을
   회색으로 채운다. 늘려서 맞추면 얼굴이 찌그러져 검출률이 떨어진다.
2. 캔버스 크기는 **stride 배수로 올림**(`snap_to_stride`). 내림하면 해상도가
   깎여 작은 얼굴이 먼저 사라진다.
3. 모델 전방 계산 → **objectness 단독**으로 점수를 매긴다. 보통은 objectness ×
   클래스 점수인데, 이 포크는 클래스 열 자리에 랜드마크가 들어 있을 수 있어
   곱하면 점수가 통째로 무너진다(실측: 영상 내내 검출 0건).
4. NMS 로 겹친 박스를 정리한다.
5. **unletterbox** — 채운 여백을 빼고 비율로 나눠 원본 좌표로 되돌린다.
   여기가 틀리면 박스가 얼굴 옆을 가린다.

끝나면 두 가지를 검사한다. **디코딩이 중간에 끊겼는지**(예상보다 20% 넘게
적으면 실패, 조금 적으면 경고) 와 **검출이 0건인지**. 검출 0건은 실패가
아니다 — 얼굴 없는 영상은 정당하게 0 이다. 다만 가중치 손상·회전 영상·잘못된
imgsz 도 똑같이 0 이 나오고 그때 **원본이 그대로 출력**되므로, 조용히 넘기지
않고 경고로 남긴다.

### ④ 추적·보간 — `tracking.py`

프레임별 박스를 **사람 단위로 잇는다**(ByteTrack). 그래야 한두 프레임 검출이
끊겨도 그 구간을 채울 수 있다.

여기 함정이 하나 있다. ByteTrack 은 매칭 비용을 `1 - IoU × 점수` 로 계산하는데
(`fuse_score`), 우리 검출 점수가 0.25 근처면 IoU 가 1 이어도 비용이 0.75 라
매칭 문턱(0.8)을 겨우 넘는다. 그러면 **트랙이 한 프레임 만에 죽는다.** 점수를
`[conf, 1] → [0.7, 1]` 로 선형 사상해서 넘긴다. 순서는 그대로라 어느 박스가 더
확실한지는 보존된다.

그다음 **끊긴 구간을 선형 보간**하고, 트랙이 끝난 뒤에도 `linger` 프레임만큼
더 가린다. 검출이 흔들리는 경계에서 얼굴이 한두 프레임 드러나는 걸 막는다.

### ⑤ 2차: 렌더 — `pipeline.py`

영상을 **다시 처음부터** 읽으며 해당 프레임의 박스에 마스킹을 얹는다
(`anonymize.py` — 모자이크·블러·박스). 박스는 `pad` 만큼 넓혀서 가린다.

`VideoWriter.write()` 는 크기가 다르면 경고만 찍고 **조용히 아무것도 안 쓴다.**
"N 프레임 완료" 를 보고하면서 재생 불가 파일이 남는다. 그래서 프레임마다
크기를 대조하고, 끝나면 1차와 프레임 수가 같은지 확인한다.

이 단계 출력은 mp4v 무음본이다. OpenCV 가 쓸 수 있는 게 그것뿐이다.

### ⑥ 인코딩·오디오·검증 — `pipeline.finalize_output()`

1. **해상도** — 짧은 변이 `FA_OUTPUT_HEIGHT` 를 넘으면 여기서 줄인다. 검출을
   원본 해상도에서 끝낸 뒤라 작은 얼굴 검출률이 안 깎인다. 확대는 안 한다.
2. **H.264 재인코딩** — mp4v 는 같은 화질에 H.264 의 약 9.5배다(1280x720 실측).
   목표 비트레이트가 있으면 그걸 쓰고, 없으면 CRF + 원본 비례 상한으로 간다.
   둘은 반대 방향의 정책이라 같이 걸지 않는다.
3. **오디오 합성** — `-shortest` 는 쓰지 않는다. 짧은 쪽에 맞춰 자르는데,
   오디오가 짧으면 잘리는 게 **영상**이다. ffmpeg 는 리턴코드 0 을 주고 파일도
   멀쩡해 보인다(실측: 20초/600프레임 → 10초/300프레임, 상태는 "ok").
4. **검증 전에는 무음본을 안 지운다.** 프레임 수를 세어 원본과 다르면 결과를
   버리고 무음본을 내보낸다. 어떤 경로로 실패하든 **익명화된 영상은 반드시
   남는다** — 오디오나 코덱 때문에 결과물이 통째로 없는 게 최악이다.

## 왜 이 패키지만 따로 두는가

`fastapi` 도 `boto3` 도 임포트하지 않는다. 의존이 한 방향이라(`service` →
`core`, 반대는 없다) 세 가지가 가능해진다.

- 코어만 쓰는 사람에게 웹 프레임워크와 AWS SDK 를 강요하지 않는다.
- 테스트가 검출기를 주입해 **torch 없이** 전 구간을 돈다.
- 배치 실행기를 붙일 때 이 패키지만 컨테이너로 떼면 된다.
