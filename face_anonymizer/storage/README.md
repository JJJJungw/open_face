# storage — S3 입출력과 이름 규칙

입력을 어디서 읽고 결과를 어디에 쓰는지, 그 이름을 어떻게 짓는지만 담당한다.

---

## 키가 만들어지는 규칙

```
v1/input/kbs/K_00000_00_0000000_0034342.mp4
        └┬┘  └──────────────┬──────────────┘
         │                  │
         │                  └─ 이름: STATE 를 deid 로 (없으면 붙여서)
         └─ 폴더: 이름 뒤에 _deid
                  │
                  ▼
v1/results/face/kbs_deid/K_00000_00_0000000_0034342_deid.mp4
└──────┬───────┘
       └─ FA_S3_OUTPUT_PREFIX
```

계산은 세 조각을 잇는 것이 전부다.

```python
output_key(key) = OUTPUT_PREFIX + output_folder(key) + output_name(key)
```

`output_folder` 는 입력의 **부모 폴더 이름 + `_deid/`**. 결과를 한곳에 몰면
폴더 하나가 몇만 건이 되고, 어느 원본 묶음에서 나온 건지 목록만 보고는 알 수
없다. 폴더가 없는 입력(직접 업로드)은 결과 프리픽스 바로 밑에 떨어진다.

`output_name` 은 이름 규칙(`naming.py`)을 따른다.

```
C_NNNNN_SS_STARTMS_ENDMS[_STATE].ext

C        카테고리 한 글자      K(kbs) · M(mbc) · S(sbs)
NNNNN    원본 영상 번호 5자리   00297
SS       세그먼트 2자리         00
STARTMS  클립 시작 ms 7자리     0000000
ENDMS    클립 끝 ms 7자리       0194281
STATE    생략(입력) / deid(출력)
```

**정체성 필드는 건드리지 않는다.** 클립을 자르거나 합치지 않으므로 번호·
세그먼트·구간은 입력 그대로여야 한다. 여기가 틀리면 결과물이 어느 원본의 어느
구간인지 추적할 수 없다.

자릿수는 고정이다. 느슨하게 받으면 정렬이 깨지고 잘못 붙은 이름이 결과 폴더에
그대로 남는다. 반대로 **대소문자와 STATE 유무는 둘 다 받는다** — 실제 버킷의
입력이 대문자에 상태 토큰이 없다. 규칙 밖 이름도 처리는 되며
`<이름>_deid.mp4` 로 떨어지고, 그때는 `parse()` 가 `None` 이라 호출자가 구분할
수 있다.

## 왜 DB 가 없는가

**결과 키가 입력 키의 순수 함수이기 때문이다.**

"이 영상 처리했나?" 를 묻는 방법이 하나뿐이다 — 그 키가 결과 버킷에 있는지
보면 된다. 별도의 상태 저장소가 필요 없고, 서버를 재시작해도 값이 같고,
나중에 배치 실행기를 붙여도 그대로 산다.

대조는 결과 프리픽스를 **한 번 나열**해서 한다(`processed_keys()`, 30초 캐시).
객체마다 HEAD 를 날리면 폴더 하나에 수백 번 왕복한다. `Delimiter` 없이
나열하므로 폴더별로 나눠 쌓아도 하위까지 한 번에 잡힌다.

남는 구멍이 하나 있다. 이 방법은 **"완료" 는 알지만 "지금 돌고 있음" 은
모른다.** 같은 폴더를 처리 중에 다시 제출하면 아직 결과가 안 올라온 건은
"미처리" 로 보인다. 결과가 깨지지는 않고(같은 키에 같은 내용을 덮어쓴다)
GPU 시간만 낭비되므로 지금은 그대로 둔다. 막으려면 작업 시작 시 0바이트
마커를 조건부 쓰기(`If-None-Match`)로 찍으면 되고, 그래도 여전히 S3 만 쓴다.

## S3 호출 — `s3.py`

boto3 는 **함수 안에서 지연 임포트**한다. S3 를 안 쓰는 사용자에게 AWS SDK 를
강요하지 않고, 테스트는 가짜 클라이언트를 주입해 네트워크 없이 돈다.

| 함수 | 하는 일 |
|---|---|
| `list(prefix)` | 한 단계만 (S3 콘솔과 같은 방식). `(폴더, 객체)` |
| `list_all(prefix)` | 하위까지 전부 |
| `output_key(key)` | 위의 키 계산 |
| `processed_keys()` | 결과 프리픽스에 이미 있는 키 집합 (캐시) |
| `download` · `upload` | 파일 왕복. 빈 파일이 내려오면 실패로 본다 |
| `presigned_url(key)` | 임시 다운로드 주소 |

botocore 예외는 `wrap()` 에서 원인이 드러나는 형태로 바꾼다 — 권한 문제와 키
오타와 네트워크 장애는 사용자가 해야 할 일이 전혀 다르다.

## 설정

```
FA_S3_BUCKET          버킷. 비면 S3 기능 자체가 꺼진다
FA_S3_REGION          리전
FA_S3_ROOT_PREFIX     브라우저 최상위 (예: v1/input/)
FA_S3_OUTPUT_PREFIX   결과물 위치 (기본: v1/results/face/)
FA_S3_LIST_TTL        '처리됨' 목록 캐시 초 (기본: 30)
FA_S3_URL_TTL         presigned URL 유효 초 (기본: 3600)
```

자격 증명은 boto3 기본 체인을 쓴다 — EC2 인스턴스 역할이 있으면 그대로 잡힌다.
