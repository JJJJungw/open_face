# storage — S3 입출력과 이름 규칙

입력을 어디서 읽고 결과를 어디에 쓰는지, 그 이름을 어떻게 짓는지만 담당한다.

| 파일 | 하는 일 |
|---|---|
| `base.py` | **저장소 계약** — 갈아 끼우려면 무엇을 지켜야 하는지 |
| `providers.py` | 어디에 붙을지. 제공자 등록표와 `StorageConfig` |
| `s3.py` | 목록·다운로드·업로드·presigned URL. boto3 는 함수 안에서 지연 임포트 |
| `transfer.py` | **서명된 URL 로만** 주고받기 — 자격 증명 0. MSA 워커 경로 |
| `naming.py` | 데이터셋 파일 이름 규칙과 입력→결과 키 변환 |
| `weights.py` | 가중치 조달. `s3` / `baked` / `url` 셋 중 하나 (스위치) |

## s3.py 와 transfer.py 는 왜 나뉘어 있나

**열쇠를 가진 쪽과 안 가진 쪽이다.** `s3.py` 는 우리 버킷에 우리 자격 증명으로
붙는다 — 단독 운영과 웹 화면이 쓴다. `transfer.py` 는 남이 열어 준 문(presigned
URL) 하나로만 드나든다 — 버킷 이름도 리전도 모른다.

후자가 따로 있는 이유는 RebornStudio 무DB 워커 규약이 "워커는 자격 증명을 갖지
않는다" 이기 때문이다. 그래야 이미지에 비밀이 하나도 안 들어가고, 워커를 다른
클러스터·계정으로 옮겨도 설정이 없다(docs/integration/rebornstudio.md).

## 이름 규칙이 왜 여기 있는가

이것이 곧 **중복 처리 방지의 근거**이기 때문이다.

```
v1/input/kbs/K_00000_00_0000000_0034342.mp4
  → v1/results/face/kbs_deid/K_00000_00_0000000_0034342_deid.mp4
```

결과 키가 입력 키의 순수 함수다. 그래서 "이 영상 처리했나?" 를 결과 버킷에
그 키가 있는지로 답할 수 있고, 별도의 DB 가 필요 없다. 서버를 재시작해도
값이 같고, 나중에 배치 실행기를 붙여도 그대로 산다.

규칙은 `C_NNNNN_SS_STARTMS_ENDMS[_STATE].ext` 이고 STATE 는 없어도 된다
(입력이 그렇게 생겼다). 규칙 밖 이름도 처리는 되며 `<이름>_deid.mp4` 로 떨어진다.


## 어디에 붙을지 — `providers.py`

지금은 AWS S3 지만 나중에 NCP 로 옮길 수 있고, 그 뒤는 아무도 모른다. 그때마다
코드를 고치는 대신 설정으로 고른다.

**대부분은 어댑터가 필요 없다.** NCP Object Storage · Cloudflare R2 · MinIO ·
Wasabi 는 전부 S3 API 를 그대로 쓴다 — 코드가 달라질 게 없고 **엔드포인트 주소만
다르다.** 그래서 `make_client()` 에 `endpoint_url` 을 넘기는 것으로 끝난다.
이걸 어댑터로 만들면 똑같은 코드를 제공자 수만큼 복사하게 된다.

| id | 이름 | 상태 |
|---|---|---|
| `s3` | AWS S3 | 엔드포인트 불필요(리전으로 정해짐) |
| `ncp` | 네이버 클라우드 Object Storage | 엔드포인트·리전 자동 |
| `s3compat` | R2 · MinIO · Wasabi … | 엔드포인트 직접 입력 |
| `gcs` `azure` | GCS · Azure Blob | **아직 없음.** 고르면 분명하게 거절한다 |

없는 것을 목록에 두는 이유는 "이건 되나?" 를 묻지 않게 하려는 것이다. 조용히
안 되는 것이 제일 나쁘다 — GCS 를 골라 뒀는데 "S3 미설정" 으로 보이면 사람이
엉뚱한 데를 고친다.

## 집안 밖을 붙이려면 — `base.py`

위의 표는 전부 S3 집안이라 주소만 다르다. GCS · Azure 처럼 **말이 아예 다른**
곳은 구현을 하나 써서 꽂아야 한다. 그때 "무엇을 쓰면 되나" 에 답하는 것이
`base.py` 다. 값 셋과 동작 열, 그게 전부다.

```
bucket  root_prefix  output_prefix
check  list  list_all  output_key  processed_keys
exists  size_of  download  upload  presigned_url
```

붙이는 일은 두 단계로 끝난다.

1. 계약을 지키는 클래스를 하나 쓴다
2. `providers.PROVIDERS[...]["store"]` 한 줄을 그 클래스로 바꾼다

부르는 쪽 열다섯 군데가 전부 `s3.get_store()` 하나를 지나가므로 고칠 데가 없다.
지원 여부(`supported`)도 그 한 줄에서 파생된다 — 따로 관리하는 목록이 없으니
둘이 어긋날 수가 없다. 이 파일조차 안 고치려면 `FA_STORAGE_STORE=모듈:클래스`
로 직접 꽂는다(등록표보다 이게 이긴다). **우리 레포를 포크할 필요가 없다.**

계약을 지켰는지는 `tests/test_storage_contract.py` 가 본다. 등록표의 모든
제공자를 실제로 불러와 만들어 본다 — 오타는 **그 제공자를 고른 날** 드러나는데
그날은 대개 이관 당일이다.

## 설정은 객체다 — `StorageConfig`

예전에는 버킷·리전이 모듈 상수라 임포트할 때 한 번 읽고 끝이었다. 설정을
바꾸려면 서버를 다시 띄워야 했고, 화면에서 고르게 하는 길이 아예 막혀 있었다.
객체로 두면 `reconfigure()` 로 갈아 끼울 수 있다.

**자격 증명은 우리가 들고 있지 않는다.** boto3 기본 체인을 쓴다 — EC2 인스턴스
역할이면 자동으로 잡히고, 다른 제공자는 환경 변수다. 파일 어디에도 키가 없는
것이 지금 구조의 장점이고, 화면에서 키를 받는 순간 그게 깨진다. 그래서
`/api/storage` 는 **읽기 전용**이다 — 화면에서 바꾸려면 **API 인증이 먼저**다.
지금은 인증이 없어서, 서버에 닿을 수 있는 누구나 키를 심거나 볼 수 있다.

## 첫 실행에는 화면에서 고른다

붙을 곳이 아직 없으면 현황 화면의 저장소 카드가 **읽기 전용 표 대신 고르는
폼**이 된다. 처음 들어온 사람을 파일 브라우저로 보내지 않는 것도 같은 이유다 —
그 화면은 빈 목록과 404 뿐이고 무엇을 해야 하는지가 어디에도 안 적혀 있다.

정하고 나면 **잠긴다.** 이 API 에는 인증이 없다. 남이 이걸 공인 IP 에 그냥
띄우는 일은 반드시 생기고, 그때 설정 화면이 계속 열려 있으면 서버에 닿는
누구나 저장소를 자기 것으로 갈아치울 수 있다. 나중에 화면에서 다시 바꿔야
하면 띄우는 사람이 `FA_ALLOW_STORAGE_EDIT=1` 로 명시적으로 연다.

**연결이 되는 것을 확인한 뒤에만 저장한다.** 첫 실행에만 열리는 문이라, 오타
하나로 잠겨 버리면 고치러 들어갈 길이 같이 막힌다.

정한 값은 `<FA_JOBS_DIR>/_storage.json` 에 남는다. **여기 비밀은 없다** —
제공자·버킷·주소·프리픽스뿐이다. 환경 변수가 이긴다.

### 열쇠는 어떻게 하나

대부분은 아무것도 안 넣어도 된다. EC2 인스턴스 역할이나 `aws configure` 가
있으면 boto3 기본 체인이 알아서 잡고, 화면은 그게 **어디서 왔는지**를 말해
준다(인스턴스 역할 · 환경 변수 · `~/.aws/credentials`). 이 한 줄이 없으면 왜
되는지 왜 안 되는지를 아무도 모른다.

없을 때만 화면이 액세스 키를 묻는다. 받은 것은 **메모리에만** 둔다 — 파일에
쓰지 않고 어떤 라우트로도 돌려주지 않는다. 웹 화면이 있는 도구인데 시작하려고
터미널을 먼저 쳐야 하는 것이 어색해서 열어 둔 길이고, 대신 재시작하면
사라진다. 그 사실을 나중에 알게 하지 않으려고 저장 직후에 환경에 넣을 두 줄을
같이 알려 준다.

## 저장소를 바꾸면 무엇이 끊기나

접속처만 바뀌는 게 아니다. `processed_keys()` 는 "이미 처리했나" 를 **결과 버킷
대조**로 판정하고, 진척률 폴더 목록(`_tracked.json`)과 저널의 폴더 이름·입력 키도
그 저장소 기준이다. 완료된 작업의 `s3_output` 은 옛 곳을 가리켜서 `/result` 가
엉뚱한 데의 서명 주소를 만든다.

즉 **저장소를 바꾸는 것은 새 작업 공간을 여는 일에 가깝다.** 설정 하나 갈아
끼우는 것처럼 만들면 사람은 가볍게 바꾸고 시스템은 조용히 틀린 상태가 된다.
화면에서 바꾸게 할 때는 그걸 먼저 알리고 확인받아야 한다.

## 붙기 전에 확인한다 — `POST /api/storage/test`

읽기와 쓰기를 **따로** 본다. 읽기만 되는 자격 증명이 흔한데 그걸 '연결됨' 이라고
하면, 900건을 다 처리하고 나서 결과를 못 올린다는 걸 알게 된다.
