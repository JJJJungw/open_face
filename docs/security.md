# 보안 — 지금 어디까지 막았고 무엇이 열려 있나

이 문서는 자랑이 아니라 **재고 목록**이다. 막은 것보다 안 막은 것을 먼저 적는다.
읽는 사람이 이걸 어디에 띄워도 되는지 판단할 수 있어야 한다.

## 한 줄

**이 서버에는 인증이 없다.** 지금은 믿을 수 있는 망 안에서 띄우는 물건이다.
공인 IP 에 그냥 올리면 안 된다.

---

## 지금 열려 있는 것

### 인증이 없다 — 가장 큰 것

모든 라우트가 열려 있다. 서버에 닿을 수 있는 사람은 누구나

- 버킷을 나열한다(`GET /api/s3/objects`) — **파일 이름 자체가 정보다.**
  방송사·날짜·프로그램이 이름에 들어 있다
- 작업을 넣고 취소하고 지운다
- 결과물의 **서명된 주소를 받아 간다**(`GET /api/jobs/{id}/result`). 그 주소는
  자격 증명 없이 열리므로 사실상 영상 반출이다
- 저널을 통째로 읽고 CSV 로 내려받는다(`GET /api/events`, `/api/export.csv`)
- 저장소를 자기 것으로 바꾸거나 끊는다

마지막 항목만 잠그는 스위치(`FA_ALLOW_STORAGE_EDIT=0`)가 있지만, 그것만으로는
**문 하나를 잠그고 나머지를 다 열어 두는 일**이다. 그래서 그 스위치를 보안
대책으로 소개하지 않는다 — 저장소 설정을 실수로 못 바꾸게 하는 용도다.

### TLS 가 없다

`uvicorn` 을 그대로 띄우면 평문이다. 화면과 API 사이의 모든 것이 그대로 흐른다.
리버스 프록시(nginx · Caddy)로 감싸는 것을 전제한다.

### 감사 기록이 부분적이다

저장소 연결·해제는 저널에 남는다(`storage.configured`, `storage.disconnected`).
**누가** 했는지는 안 남는다 — 인증이 없으니 남길 이름이 없다.

---

## 막은 것

### 열쇠는 평문 연결로 안 받는다

첫 화면에서 액세스 키를 받을 수 있는데, **https 이거나 루프백일 때만** 받는다.
리버스 프록시 뒤라면 `X-Forwarded-Proto` 를 본다. 평문이면 400
`insecure_transport` 로 거절하고, 화면은 아예 입력칸을 열지 않는다.

평문으로 온 키는 이미 경로 위의 누구나 봤다고 봐야 한다. 그걸 받아서 "메모리에만
둡니다" 라고 하면 **안전하게 다뤘다는 인상만 주고 실제로는 아니다.**

### 열쇠는 파일에 안 쓰고 돌려주지도 않는다

화면에서 받은 키는 메모리에만 있다. `_storage.json` 에는 제공자·버킷·주소·
프리픽스만 들어간다. 어떤 라우트도 키 값을 돌려주지 않는다 — **어디서 왔는지**
(인스턴스 역할 · 환경 변수 · `~/.aws/credentials`)만 말한다.

대부분의 배포는 키를 아예 안 넣는다. EC2 인스턴스 역할이면 자동으로 잡힌다.

### 엔드포인트 주소를 검사한다 (SSRF)

엔드포인트는 **서버가 대신 요청을 보낼 주소**다. 화면에서 받는 순간 임의의
주소로 요청을 보내게 만들 수 있는 통로가 열린다. 우리 서버는 VPC 안에 있고
인스턴스 역할을 달고 있어서, 바깥에서는 못 닿는 곳에 닿는다.

막는 것은 셋이다. `http`·`https` 가 아닌 스킴, 주소에 박은 아이디·비밀번호,
그리고 **링크 로컬 주소**(`169.254.169.254` 가 대표 — 여기는 인스턴스 역할의
임시 키를 그대로 내준다). 사설 IP 는 막지 않는다. MinIO 를 사내망에 두는 것이
정상적인 용법이라 그걸 막으면 지원한다고 해 놓고 못 쓰게 하는 셈이다.

남은 구멍: **DNS 리바인딩.** 검사할 때 해석한 주소와 boto3 가 실제로 붙을 때
해석하는 주소가 다를 수 있다. 인증이 붙기 전까지는 이 공격을 할 수 있는 사람이
이미 더 쉬운 길을 갖고 있어서 뒤로 미뤘다.

### 모듈 경로는 요청이 고를 수 없다

`FA_STORAGE_STORE` 는 파이썬 모듈 경로이고 `import_module()` 에 들어간다.
**임포트만으로 코드가 도는 모듈은 얼마든지 있다.** 한때 이 값을
`POST /api/storage` 본문에서 받고 있었는데, 그건 인증 없는 요청에게 우리 서버에서
무엇을 실행할지 고르게 해 주는 일이었다. 지금은 환경 변수로만 정한다 — 구현을
갈아 끼우는 것은 **서버를 띄우는 사람의 일**이다.

### 저장소를 끊을 때 돌던 작업을 지킨다

작업이 진행·대기·검수 대기 중이면 연결 해제를 409 로 거절한다. 그 밑에서
저장소를 빼면 그 작업은 결과를 올릴 곳을 잃는다.

## 지금 안전하게 띄우는 법

**믿을 수 있는 망 안에 두고, 바깥에서는 SSH 터널로 본다.** 지금 우리가 쓰는
방식이고, 인증이 붙기 전까지 권하는 방식이다.

```
서버 쪽   uvicorn ... --host 127.0.0.1 --port 8000
보는 쪽   ssh -N -L 8000:127.0.0.1:8000 <서버>
```

`--host 0.0.0.0` 은 보안 그룹이 특정 IP 만 열어 두는 경우에만 쓴다. 그때도
리버스 프록시로 TLS 를 씌우는 편이 낫다 — 화면이 키 입력을 열어 주는 조건이기도
하다.

## 다음에 할 것 (순서대로)

1. **인증.** 이것 하나가 위의 절반을 덮는다. 형태는 아직 안 정했다 — 공유
   토큰 하나로 갈지, 아이디·비밀번호로 갈지, 조직 SSO(OIDC)에 붙일지는 이
   도구를 누가 쓰느냐에 달려 있다.
2. **TLS 를 기본 경로로.** 리버스 프록시 설정 예시를 저장소에 넣는다.
3. **감사 기록에 주체를 남긴다.** 1번이 되면 자연히 따라온다.
4. **결과물 서명 주소의 수명을 줄인다.** 지금 한 시간(`FA_S3_URL_TTL`)이다.
   주소 하나가 새면 그동안 누구나 열 수 있다.
5. **DNS 리바인딩.** 검사한 IP 로 직접 붙게 한다.
