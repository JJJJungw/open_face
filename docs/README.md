# docs — 문제와 해결 기록

이 폴더는 **이 서비스를 만들면서 실제로 겪은 문제와, 그것을 어떻게 판단하고
고쳤는지**를 남긴다. 기능 설명서가 아니다. 기능은 각 폴더의 README 에 있다.

## 왜 따로 남기는가

고친 코드만 보면 "왜 그렇게 고쳤는지" 가 사라진다. 특히 **고르지 않은 선택지**
가 사라진다 — 더 쉬운 방법이 있는데 왜 그걸 안 썼는지, 어떤 대가를 받아들였는지.
그게 없으면 다음 사람이(또는 반년 뒤의 내가) 같은 자리를 원래대로 되돌린다.

## 쓰는 순서

1. **문제를 먼저 쓴다.** 고치기 전에 쓴다. 증상·재현·원인·영향까지.
   고친 뒤에 쓰면 이미 답을 아는 상태라 "그때는 왜 몰랐는지" 가 빠진다.
2. 고친다.
3. **해결 방법과 검증을 덧붙인다.** 무엇을 골랐고 무엇을 버렸는지, 그게
   실제로 고쳐졌다는 근거는 무엇인지.

## 형식

`issues/NNN-제목.md`. 번호는 발견한 순서다. 각 문서는 이 뼈대를 따른다.

```
상태      미해결 | 해결됨 (커밋 해시)
한 줄     무엇이 문제인가
증상      무엇이 보이는가
재현      어떻게 확인하는가
원인      코드 어디가, 왜 그렇게 되어 있었나
영향      실제로 얼마나 나쁜가 — 되도록 숫자로
─────────── 여기까지 고치기 전에 쓴다 ───────────
해결      무엇을 골랐나
버린 선택 왜 다른 방법을 안 썼나
검증      고쳐졌다는 근거
배운 것   다음에 같은 실수를 안 하려면
```

## 이미 고친 것들

아래는 이 문서 체계를 만들기 전에 겪고 고친 것들이다. 기록 형식이 자리잡은 뒤
같은 뼈대로 옮길 예정이다.

| 문제 | 어떻게 드러났나 | 커밋 |
|---|---|---|
| `-shortest` 가 영상을 잘랐다 | 20초/600프레임 결과물이 10초/300프레임인데 상태는 `ok` | — |
| ByteTrack 이 한 프레임 만에 죽었다 | 점수 정규화 없이 `fuse_score` 문턱을 못 넘었다 | — |
| AV1 원본에 비트레이트 상한을 그대로 걸었다 | 결과물이 3.4배 눌려 벽이 블록으로 깨졌다 | `5fad256` |
| 결과물이 입력에 섞여 다시 처리됐다 | `_deid` 파일의 결과 키가 자기 자신이라 안 걸렸다 | `29050bb` |
| `.env` 파서가 줄 끝 주석을 값에 넣었다 | 배포한 예시 파일이 정작 파싱되지 않았다 | — |
| 리팩토링 뒤 기본 경로가 패키지 안쪽을 가리켰다 | 가중치가 엉뚱한 곳에 받아지고 서버는 기동에서 터졌다 | — |
