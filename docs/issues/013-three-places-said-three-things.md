# 013 — 화면 세 곳이 모델에 대해 서로 다른 말을 했다

## 증상

같은 순간에 이랬다.

| 자리 | 문구 |
|---|---|
| 연결 팝오버 | **모델 준비됨** · 모델 가중치 있음 (37.9 MB) |
| 상단 배지 | **모델 준비 중** |
| 사이드바 | **준비 중** · 모델을 올리는 중 |

셋 다 자기 딴에는 맞는 말이었다. 그래서 더 나빴다 — 하나가 틀렸으면 그걸
고치면 되는데, 셋 다 맞으면 **어느 것을 믿어야 할지가 없다.**

## 원인 — 사실이 둘인데 이름이 하나였다

    가중치 파일   디스크에 파일이 있나            (storage/weights)
    모델         메모리에 올라와서 지금 처리되나  (service/worker)

`FA_PRELOAD=0` 으로 띄우면 **파일은 있는데 모델은 안 올라와 있다.** 첫 요청이
와야 올린다. 즉 위의 세 문구는 서로 다른 사실을 말하고 있었고, 전부 "모델" 이라는
같은 단어를 썼다.

셋 중 팝오버가 내 실수다. 042 에서 가중치 상태를 화면에 붙이면서
`weights.present`(파일이 있나)를 보고 "모델 준비됨" 이라고 적었다. 파일이 있는
것과 모델이 올라온 것은 다른 일인데 이름을 같이 썼다.

## 덤으로 나온 것 — 배지는 기동 때 한 번만 그려지고 있었다

상단 배지는 페이지가 뜰 때 `/api/health` 를 한 번 부르고 끝이었다. 그래서 모델이
다 올라온 뒤에도 **"모델 준비 중" 이 영원히 붙어 있었다.** 새로고침해야 바뀐다.
이건 042 와 무관한 예전 버그인데, 세 문구를 나란히 놓고 보니 드러났다.

## 한 일

**어휘를 나눴다.** '모델' 은 메모리에 올라온 것에만 쓰고, 디스크의 파일은
'가중치 파일' 이라고 부른다. 팝오버의 줄 이름도 그렇게 바꿨다.

**문구를 한 곳에서 정한다.** `modelState(st)` 하나가 서버 상태를 받아
`모델 준비됨` / `모델 올리는 중` / `모델 로드 실패` / `서버 연결 끊김` 중 하나를
돌려준다. 배지도 사이드바도 팝오버도 이걸 쓴다. 앞으로 문구를 바꿀 일이 생기면
고칠 자리가 하나다.

**배지를 폴링에 붙였다.** 상태가 준비됨으로 바뀌면 그때 장치 정보를 한 번 받아
와서 `cuda:0 · half=true · imgsz 1280` 로 바꾼다. 준비되기 전에는 진행 문구를
띄운다.

## 확인

모델을 안 올린 서버와, 4초 뒤에 올라오는 서버를 각각 띄워 브라우저로 봤다.

```
안 올라온 상태   배지 "모델 올리는 중" · 사이드바 "모델 올리는 중" · 팝오버 "모델 올리는 중"
4초 뒤          배지 "cuda:0 · half=true · imgsz 1280" · 사이드바 "유휴" · 팝오버 "모델 준비됨"
```

새로고침 없이 따라간다.

## 남겨 둘 것

이런 종류의 버그는 **각 화면이 자기가 편한 값을 직접 읽을 때** 생긴다. 문구를
서버가 정해서 내려보내는 자리(`events.decorate`, `timefmt`)에서는 안 나던
문제다. 화면 쪽에도 같은 원칙을 적용할 자리가 더 있을 수 있다.
