# 025 — 관문이 잘못된 순서로 물었고, 안 되는 이유는 한 가지로만 답했다

**상태** 해결됨

깡통 서버에 이걸 처음 올린 사람이 보는 화면이 첫 관문이다. 그 화면이 묻는 순서는
이랬다.

```
1. 제공자 칩
2. 버킷 이름          ← 첫 입력
3. 엔드포인트
4. 리전
5. 입력 프리픽스
6. 결과 프리픽스
7. 자격 증명 — 없습니다   ← 상태만. 뭘 어쩌라는 말은 없다
8. 모델 가중치
9. 액세스 키 / 시크릿 키  ← 맨 아래
```

## 증상

사람은 위에서부터 채운다. 버킷 이름을 넣고 저장을 누르면 이게 돌아왔다.

```
S3 호출에 실패했습니다
리전 설정과 네트워크 상태를 확인해 주세요.
```

리전도 망도 멀쩡하다. 없는 것은 **열쇠**다. 화면은 일곱 번째 줄에 "없습니다" 라고
적어 두긴 했지만 그건 상태 표시였고, 그 사람이 다음에 무엇을 해야 하는지는
어디에도 없었다.

## 원인 — 둘이다

### 하나. 순서가 안내를 대신하고 있었다

우리는 개발하면서 EC2 에 `aws configure` 를 이미 해 뒀다. 그래서 이 화면을
**자격 증명이 이미 있는 상태로만** 봤다. 그 상태에서는 버킷 이름이 첫 칸인 게
자연스럽다. 처음 받는 사람에게는 아니다.

### 둘. 안 되는 이유 다섯이 한 문장으로 뭉쳐 있었다

`storage/s3.py` 의 `wrap()` 은 botocore 예외의 `response["Error"]["Code"]` 로
갈래를 정했다. 그런데 **자격 증명이 아예 없을 때 botocore 가 던지는 예외에는
`response` 가 없다.** HTTP 요청을 보내지도 못했으니 응답이 있을 리 없다.

```python
code = ""                      # NoCredentialsError → 여기가 빈 문자열
...
else:
    err.problem = errors.S3_UPSTREAM        # "리전과 네트워크를 확인하세요"
```

`S3_UPSTREAM` 은 `retryable=True` 다. 그래서 워커는 **절대 성공할 수 없는
호출을 95초짜리 재시도 창 안에서 네 번 반복**했다. 키 오타(`InvalidAccessKeyId`)
와 권한 없음(`AccessDenied`)도 한 딱지로 뭉쳐 있었고, 없는 버킷은 "해당 파일을
찾지 못했습니다" 로 나왔다 — 파일이 아니라 버킷인데.

## 영향

| 실제 원인 | 예전에 보이던 말 | 사람이 뒤진 곳 |
|---|---|---|
| 키가 없다 | 리전 설정과 네트워크 상태 | 리전 · 보안 그룹 |
| 키가 틀렸다 | S3 접근 권한이 없습니다 | IAM 정책 |
| 권한이 없다 | S3 접근 권한이 없습니다 | (맞다) |
| 버킷이 없다 | 해당 **파일**을 찾지 못했습니다 | 키 경로 |
| 못 닿는다 | 리전 설정과 네트워크 상태 | (맞다) |

다섯 중 셋이 틀린 곳을 가리켰다. 그리고 그중 둘은 재시도까지 태웠다.

## 해결

### 게이트는 셋으로 나누고 번호를 붙인다

```
1. 어디에 붙일까요      제공자 칩
2. 무엇으로 붙을까요    지금 자격 증명 · 제공자별 사실 · 키 입력
3. 어느 칸에 넣을까요   버킷 · 엔드포인트 · 리전 · 프리픽스
```

**붙을 수 있어야 주소가 의미가 있다.** 그래서 자격 증명이 먼저다.

### 자격 증명 안내는 제공자가 선언한다

`storage/providers.py` 의 각 제공자에 `credentials` 를 뒀다.

```python
"credentials": {
    "where":   "IAM 콘솔 → 사용자 → 보안 자격 증명 → 액세스 키",
    "url":     "https://console.aws.amazon.com/iam/",
    "ambient": "이 서버가 EC2·ECS 이고 IAM 역할이 붙어 있으면 …",
    "env":     ("AWS_ACCESS_KEY_ID", "AWS_SECRET_ACCESS_KEY"),
}
```

화면은 고른 제공자의 그 값을 그대로 그린다. NCP 를 고르면 `ambient` 가 비어
있으므로 "키가 있어야 붙습니다" 로 바뀌고, 발급처도 네이버 콘솔로 바뀐다.
**화면이 AWS 를 특별대우하는 게 아니라, 키 없이 붙는 길이 AWS 에만 있다는 것이
그냥 사실이다** — 클라우드에 종속돼 보이던 문제가 여기서 같이 풀린다.

`env` 가 전부 `AWS_` 로 시작하는 것은 우리 사정이 아니라 boto3 의 이름이다.
NCP 사용자가 "왜 AWS 변수지?" 에서 멈추지 않게 화면에 그대로 적는다.

### 안 되는 이유를 다섯으로 쪼갠다

```
키가 없다     s3_no_credentials    넣거나 환경에 둔다        재시도 ✗
키가 틀렸다   s3_bad_credentials   키를 다시 본다            재시도 ✗
권한이 없다   s3_access_denied     콘솔에서 정책을 고친다    재시도 ✗
버킷이 없다   s3_bucket_not_found  이름·리전을 다시 본다     재시도 ✗
못 닿는다     s3_upstream          주소·망을 본다            재시도 ○
```

자격 증명 부재는 **클래스 이름**으로 잡는다(`NO_CREDENTIAL_ERRORS`). botocore 를
임포트해서 예외 클래스를 잡으면 boto3 가 없는 워커 환경에서 이 모듈이 통째로 못
뜬다 — 024 에서 이미 한 번 밟은 자리다.

### 열쇠 칸을 이제 숨기지 않는다

예전에는 자격 증명이 하나라도 잡히면 칸을 숨기고 "이미 있어서 따로 넣지 않으셔도
됩니다" 라고 했다. **잡힌 것이 고른 제공자의 것이라는 보장이 없다.**
`~/.aws/credentials` 가 있는 기계에서 NCP 를 고르면 그 문장이 뜨고, 그대로
저장하면 거절당한다. 그때 사람은 이미 "안 넣어도 된다" 는 말을 들은 뒤라 열쇠를
마지막에 의심한다.

이제는 있으면 있다고만 말하고(`지금 자격 증명 — ~/.aws/credentials`), 칸은
`(선택)` 으로 열어 둔다.

## 버린 선택

**IAM 역할 붙이는 법을 화면에서 안내하기.** 처음에 그러려고 했다. 그런데 그건
우리 화면이 해 줄 수 있는 게 하나도 없는 이야기다 — 콘솔에 가서 인스턴스에
역할을 붙이는 일이고, 그 사람의 계정 일이다. 우리가 답해야 하는 질문은 넷뿐이다.

> 지금 자격 증명이 있나 · 없으면 여기서 받고 · 실제로 붙나 · 안 붙으면 왜 안 붙나

그래서 표에 적는 것도 **안내가 아니라 사실**로 좁혔다. 어디서 발급받는지,
키 없이 붙는 길이 있는지까지. 그 뒤는 링크 하나로 넘긴다.

**`.env` 에 키를 적으라고 안내하기.** 그러면 오픈소스로 받는 사람 전원이 평문
파일에 열쇠를 두게 된다. 지금 구조는 boto3 기본 체인을 그대로 쓰므로 인스턴스
역할·`aws configure`·환경 변수·화면 입력이 전부 성립하고, 화면은 그중 **무엇이
잡혔는지**만 말한다. 어느 하나를 강요하지 않는다.

**평문 http 에서도 키를 받기.** 안 연다. 넣는 즉시 경로 위의 누구나 본다.
localhost 와 SSH 터널은 `isSecureContext` 로 통과하므로, 자기 기계에서 돌리는
사람은 막히지 않는다.

## 배운 것

**개발자는 자기 기계의 상태를 화면에서 못 본다.** 이 관문은 자격 증명이 이미
있는 상태에서만 검토됐다. 없는 상태로 열어 본 적이 한 번도 없어서, 그 사람에게
화면이 무슨 말을 하는지가 아무에게도 안 보였다.

**"안 됩니다" 는 답이 아니다.** 안 되는 이유가 다섯인데 문구가 하나면, 그 하나가
넷에게 틀린 말을 한다. 그리고 그 틀린 말이 재시도까지 태우면 낭비가 조용히 붙는다.

**안내와 사실은 다르다.** 사실은 우리가 아는 것이고(이 제공자는 키가 필요하다),
안내는 그 사람이 해야 하는 것이다(IAM 정책을 이렇게 짜세요). 사실만 적으면
제공자가 늘어도 유지되고, 안내를 적기 시작하면 남의 콘솔 UI 를 따라다니게 된다.
