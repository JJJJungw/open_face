# 011 — 저장소는 "고를 수 있어야" 했는데 고를 수 있는 건 주소뿐이었다

## 요구

붙을 클라우드가 안 정해졌다. 지금은 AWS S3 고, 곧 NCP 로 옮길 수 있고, 그 뒤는
아무도 모른다. 그래서 **처음부터 고를 수 있는 모양**이어야 한다는 것이 요구였다.

## 037 이 한 것과 못 한 것

037 에서 `providers.py` 를 만들어 제공자를 설정으로 골랐다. 그런데 그건
**S3 집안 안에서만** 고르는 것이었다. AWS · NCP · R2 · MinIO · Wasabi 는 전부
S3 API 를 그대로 쓰므로 엔드포인트 주소만 바꾸면 되고, 실제로 그렇게 된다.

집안 밖은 아니었다. GCS 나 Azure 를 고르면 `supported=False` 로 거절하는데,
**거절 다음에 뭘 하면 되는지가 아무 데도 없었다.** 붙이려는 사람은 `s3.py`
900 줄을 읽고 어디까지가 계약이고 어디부터가 S3 사정인지 추측해야 한다.
"고를 수 있는 설계" 라기보다 "지금 되는 것만 되는 설계" 였다.

## 이미 있었던 것 — 틈은 있었고 이름이 없었다

테스트가 `S3Store` 대신 완전히 다른 객체를 꽂아 서버 전체를 돌리고 있었다.
boto3 도 네트워크도 없이 돈다. 부르는 쪽은 열다섯 군데인데 **전부
`s3.get_store()` 하나를 지나간다.** 즉 갈아 끼우는 자리는 원래 있었고, 적어
두지 않았을 뿐이다. 그래서 새로 만든 게 아니라 이름을 붙였다.

## 한 일

**`storage/base.py` — 계약.** 값 셋(`bucket`, `root_prefix`, `output_prefix`)과
동작 열(`check` `list` `list_all` `output_key` `processed_keys` `exists`
`size_of` `download` `upload` `presigned_url`). 부르는 쪽에서 실제로 쓰는 것만
넣었다 — 계약이 넓어지면 새 저장소를 붙이기가 그만큼 어려워진다. 테스트가 그
크기를 지킨다.

**꽂는 자리를 한 곳으로.** 제공자마다 `store` 에 `"모듈:클래스"` 가 적혀 있고
`get_store()` 가 그걸 불러온다. GCS 구현을 넣는 날 고칠 곳은 그 한 줄이다.
문자열로 두고 부를 때 불러오므로, 새 저장소가 무거운 의존성을 들고 와도 그걸
고른 사람만 값을 치른다.

**지원 여부를 파생시켰다.** 예전에는 `s3_compatible` 로 판단했다. 그러면
구현을 넣는 날 고칠 자리가 둘이 되고(등록 + 지원 목록), 하나를 빠뜨리면
"지원 안 함" 인데 동작하거나 그 반대가 된다. `store` 한 줄에서 파생시키면
어긋날 수가 없다.

**`FA_STORAGE_STORE`.** 등록표조차 안 고치고 환경 변수로 직접 꽂는 길. 우리가
모르는 저장소를 쓰게 될 쪽이 우리 레포를 포크해야 한다면 그건 '고를 수 있다'
가 아니다.

**`NotImplementedStore`.** GCS · Azure 자리를 채운다. 계약의 이름은 다 갖고
있어서 꽂는 자리가 실제로 있다는 것은 증명하되, 부르면 분명하게 거절한다.
**조용한 목업이 제일 나쁘다** — 빈 목록을 돌려주는 가짜를 두면 화면에
"폴더 0개" 가 뜨고 사람은 버킷이 비었다고 믿는다.

## 증명

`tests/test_storage_contract.py` 가 등록표의 모든 제공자를 실제로 불러와
만들어 보고 계약을 대조한다. 오타는 그 제공자를 고른 날 — 대개 이관 당일에 —
드러나기 때문이다.

말로 끝내지 않으려고 실제로 꽂아 봤다. S3 를 하나도 안 쓰고 로컬 디렉터리로
도는 스토어를 짜서 `FA_STORAGE_STORE=mystore:LocalStore` 로 서버를 띄웠다.
**우리 코드는 한 줄도 안 고쳤다.**

```
GET /api/storage      → store: "mystore:LocalStore", ready: true
GET /api/s3/objects   → folders: ["in/kbs/", "in/mbc/"]
POST /api/storage/test → ok: true, "읽기와 쓰기 모두 확인했습니다"
```

## 그다음 — 화면에서 고르기 (첫 실행만)

여기까지 하고 보니 요구의 나머지 절반이 남아 있었다. 남이 클론해 와서 서버를
띄우면 **뭘 해야 하는지가 화면 어디에도 없었다.** 버킷이 없으니 파일 브라우저는
빈 목록과 404 뿐이고, 답은 `.env.example` 을 열어야 나온다. 웹 화면이 있는
도구인데 시작하려면 터미널을 먼저 쳐야 한다는 뜻이다.

막고 있던 것은 기술이 아니라 **인증**이다. 설정을 열면 서버에 닿는 누구나
저장소를 자기 것으로 갈아치울 수 있다. 그래서 문을 여는 조건을 좁혔다.

**첫 실행에만 연다.** 아직 아무것도 안 정해졌으면 화면에서 정할 수 있고, 한 번
정해지면 잠긴다. 아직 안 정해진 서버에는 가로챌 것도 없으니, 위험이 실제로
있는 구간에서는 문이 이미 닫혀 있다. 나중에 바꿔야 하면 띄우는 사람이
`FA_ALLOW_STORAGE_EDIT=1` 로 명시적으로 연다 — 기본이 잠김이라 모르고 노출될
일이 없다.

**되는 것을 보고 나서 저장한다.** 첫 실행에만 열리는 문이라 오타 하나로 잠기면
고치러 들어갈 길이 같이 막힌다. 읽기·쓰기를 실제로 해 보고 나서 저장하면 그
사고가 성립하지 않는다. 실패하면 있던 설정으로 되돌린다.

**첫 실행이면 파일 브라우저로 안 보낸다.** 지금 할 수 있는 일이 하나뿐이면
그게 첫 화면이어야 한다. 저장소 카드가 맨 위로 올라오고 폼이 열린다.

### 열쇠

대부분은 안 넣는다 — EC2 인스턴스 역할이나 `aws configure` 가 있으면 boto3
기본 체인이 잡는다. 화면은 그게 **어디서 왔는지**를 말해 준다. 이 한 줄이
없으면 왜 되는지 왜 안 되는지를 아무도 모른다.

없을 때만 묻고, 받은 것은 **메모리에만** 둔다. 파일에 안 쓰고 어떤 라우트로도
안 돌려준다. 재시작하면 사라지므로 저장 직후에 환경에 넣을 두 줄을 같이 알려
준다 — 사라진다는 걸 사라진 뒤에 알게 하지 않는다.

### 확인한 것

실패가 저장을 막는가(오타 버킷·쓰기 권한 없음), 저장 뒤에 잠기는가, 잠긴 뒤
요청이 409 이고 원래 값이 그대로인가, 스위치로 다시 열리는가, 파일에 비밀이
안 들어가는가, 응답에 키가 안 나오는가, 재시작 뒤 설정은 살고 키는 사라지는가,
환경 변수가 이기는가, 설정 파일이 깨져도 서버가 뜨는가. 화면 쪽은 실제 브라우저로
오타 → 거절 → 정정 → 저장까지 눌러 봤다.

## 남은 것

저장소를 바꾸는 것은 접속처만 바꾸는 게 아니다. "이미 처리했나" 판정이
결과 버킷 대조이고 진척률 폴더와 저널의 폴더 이름도 그 저장소 기준이라,
바꾸면 **이미 처리한 것이 전부 미처리로 보인다.** **첫 실행 화면은 이 경고를 안 띄운다** —
아직 바꿀 것이 없기 때문이다. `FA_ALLOW_STORAGE_EDIT` 로 다시 열어 이미 돌던
저장소를 바꾸는 경우에는 그걸 먼저 알려야 하고, 아직 안 만들었다.

그리고 인증은 여전히 없다. 첫 실행 문을 좁힌 것은 그 문제를 **미룬** 것이지
푼 것이 아니다.

## MSA 쪽은 해당 없음

저쪽 서버에서 도는 경로는 애초에 저장소를 모른다. 서명된 URL 만 받으므로 버킷
이름도 제공자 설정도 열쇠도 없다. 저쪽이 어디로 옮기든 서명하는 쪽만 바뀐다
(`docs/integration/rebornstudio.md` §2-2).
