# 007 · 잘못 넣은 배치를 한 번에 멈출 수 없다

**상태** 해결됨

**한 줄** 취소는 작업 한 건 단위로만 있다. 폴더를 잘못 넣으면 300개의 카드에서
'취소' 를 300번 눌러야 한다. 그리고 화면은 큐가 **어떤 모양인지** 를 보여 주지
않는다 — 카드 목록은 개별 작업을 보는 도구다.

## 증상

`kbs/` 를 통으로 넣었는데 파라미터가 틀렸다는 것을 첫 결과물을 보고 알았다.
이때 할 수 있는 일은 셋뿐이었다.

1. 카드마다 '취소' 를 누른다 — 297번
2. 서버를 Ctrl+C 한다 — 그런데 재시작하면 대기가 **다시 큐에 들어간다**
   (docs/issues/002 에서 일부러 그렇게 만들었다)
3. `jobs/` 디렉터리를 손으로 지운다 — 돌고 있는 작업과 경합한다

**002 에서 만든 복구 로직이 여기서는 정확히 반대로 작동한다.** 유실을 막으려고
만든 것이 "그만두고 싶다" 를 막는다. 둘 다 필요한 기능인데 서로를 모른다.

## 재현

폴더 하나를 제출하고 전부 멈추려고 시도한다.

```bash
curl -s localhost:8000/api/status | python3 -c "import sys,json;print(json.load(sys.stdin)['counts'])"
# {'queued': 296, 'running': 1, ...}
# 여기서 한 번에 멈출 방법이 없다
```

## 원인

기능이 없다. 설계상 빠뜨린 것이라기보다, **취소를 "작업의 속성" 으로만 봤고
"큐의 동작" 으로는 보지 않았다.** 한 건을 멈추는 것과 큐를 비우는 것은 다른
행위인데 전자만 만들었다.

한 건씩 라우트를 300번 부르는 것으로 대신할 수도 없다. 그 사이에도 워커는 큐를
계속 꺼내므로 **앞에서 취소하는 동안 뒤에서 새 작업이 시작된다.**

## 영향

GPU 시간이다. 297건짜리 배치를 한 건 41초로 잡으면 3시간 20분. 잘못 넣은 것을
알아차린 시점이 3분째라면 나머지 3시간 17분이 그대로 낭비된다. 그리고 그 사이
결과 버킷에는 **버려야 할 결과물이 쌓인다** — 지우는 일이 또 남는다.

## 해결

### 1. `POST /api/jobs/cancel-all`

```python
def cancel_all():
    with LOCK:
        rows = [j for j in JOBS.values() if j.status in ("queued", "running")]
        for j in rows:
            j.cancel = True
            if j.status == "queued":
                j.status, j.finished = "cancelled", now
```

**대기는 즉시, 수행중은 표시만.** 대기는 아직 아무것도 시작하지 않아 상태만
바꾸면 끝이다. 수행중은 프레임 경계에서만 안전하게 끊을 수 있으므로 004 에서
만들어 둔 협조적 취소 지점을 그대로 쓴다 — 플래그를 세우면 워커가 다음 진행
보고에서 스스로 빠져나오고, 몇 초 안에 멈춘다.

**락 한 번 안에서 전부 표시하는 것**이 핵심이다. 그래야 취소하는 동안 워커가
다음 작업을 시작하는 틈이 없다.

수행중 작업의 상태를 여기서 `cancelled` 로 바꾸지 않는 이유도 같은 자리에 있다.
프레임 경계 밖에서 상태를 바꾸면, 워커가 그 뒤에 결과를 쓰면서 **취소한 작업이
완료로 되살아난다.** 상태를 바꾸는 주인은 워커 하나여야 한다.

라우트 선언 순서도 걸린다. `/api/jobs/cancel-all` 을 `/api/jobs/{jid}/cancel`
뒤에 두면 `cancel-all` 이 작업 id 로 잡힌다.

### 2. 버튼은 목록 밖에, 두 단계로

카드마다 있는 '취소' 와 같은 자리에 두면 안 된다. 한 건을 멈추는 것과 전부를
멈추는 것은 되돌릴 수 없는 정도가 다르다. 목록 머리의 오른쪽 끝에 따로 두고,
누르면 바로 실행하지 않고 한 번 더 묻는다.

```
진행중 285건을 전부 멈춥니다. S3 파일은 그대로입니다.  [전부 멈춤] [아니오]
```

문구에 **S3 는 건드리지 않는다**고 적는다. 여기서 사라지는 것은 아직 하지 않은
일과 하던 일의 중간 산물뿐이고, 원본도 이미 올라간 결과물도 그대로다. 그걸
모르면 누르기가 무섭다.

끝난 것을 보는 화면(완료·실패·전체 기록)에는 이 버튼을 두지 않는다. 그 화면의
카드는 취소할 수 있는 것이 아니라서, 버튼이 무엇을 멈추는지 읽히지 않는다.

### 3. 큐 화면 — 무엇이 들어오고 무엇이 나가는가

카드 목록은 작업 **한 건**을 보는 도구다. 큐가 어떤 모양인지는 못 보여 준다.
대기 화면 위에 흐름을 하나 둔다.

```
┌ 들어와 있는 것 ─┐   ┌ 처리중 ───────────┐   ┌ 나간 것 ────────┐
│ 284건           │ ▶ │ K_00012...mp4     │ ▶ │ 12건            │
│ 가장 오래 3:41  │   │ 검출 17% · 남은 48초│   │ 최근 1시간 12건 │
└─────────────────┘   └───────────────────┘   └─────────────────┘
다음 차례  K_00013 · K_00014 · K_00015 · K_00016 · K_00017
```

'가장 오래 기다린 건' 을 넣은 이유는 깊이만으로는 정체를 못 보기 때문이다.
100건이 1분 만에 빠지는 것과 3건이 두 시간째 멈춰 있는 것은 다른 상황이다.

### 4. 탭마다 다른 화면

사이드바를 눌러도 같은 타일 넉 장이 그대로면, 사이드바는 목록 필터 하나짜리로
되돌아간다. 탭마다 숫자를 바꿨다.

| 화면 | 무엇을 답하는가 |
|---|---|
| 진행중 | 언제 끝나나 — 전체 남은 시간·수행중·대기 |
| 수행중 | 지금 이 한 건이 어디까지 왔나 — 진행률·단계·속도 |
| 대기 | 얼마나 밀렸나 — 대기 건수·예상 소요·다음 차례 + 큐 흐름 |
| 완료 | 얼마나 빨랐나 — 평균 처리 시간·실시간 대비·최근 1시간 |
| 실패 | 왜 실패했나 — 실패율·재시도 건수·취소 건수 |
| 전체 기록 | 이 서버가 기억하는 전부 |

한 쪽에 카드 5장. 카드는 크고, 큐 전체의 모양은 카드가 아니라 큐 흐름이
보여 준다. `FA_PAGE_SIZE` 로 바꿀 수 있다.

## 버린 선택

**서버를 재시작해서 큐를 비운다.** 002 를 되돌리는 셈이다. 유실 방지와 중단은
둘 다 필요한 기능이고, 하나를 위해 다른 하나를 끄면 안 된다.

**`DELETE /api/jobs` 로 큐를 지운다.** 지우는 것과 멈추는 것은 다르다. 기록이
남아야 "무엇을 취소했는지" 를 볼 수 있고, 잘못 눌렀을 때 무엇이 사라졌는지
확인할 수 있다. 취소된 작업은 `cancelled` 로 남는다.

**확인 창(`confirm()`).** 브라우저 모달은 화면을 통째로 막고, 자동화 검증에서
폴링까지 멈춘다. 같은 자리에서 버튼이 한 번 더 묻는 쪽이 싸고 안전하다.

**필터/폴더 단위 부분 취소.** kbs 만 취소하고 mbc 는 남기는 것도 자연스럽지만,
버튼 하나가 무엇을 멈출지가 **화면 상태에 따라 변한다.** 되돌릴 수 없는 동작의
범위가 눈에 보이지 않는 곳(지금 어떤 탭인지)에 숨는 건 위험하다. 전체 취소는
언제나 같은 것을 멈춘다.

## 검증

테스트 셋.

| 무엇을 지키는가 |
|---|
| 한 번 호출로 대기 전부가 `cancelled`, 수행중은 중단 표시 |
| 끝난 기록(`done`)은 건드리지 않는다 |
| **수행중은 상태를 바꾸지 않는다** — 바꾸면 워커가 나중에 완료로 되살린다 |
| 빈 큐에서 불러도 오류가 아니다 (`cancelled: 0`) |

화면은 297건 상태를 헤드리스 브라우저로 띄워 탭마다 실제로 다른 값이 나오는지,
전체 취소가 두 단계로 동작하는지 확인했다. 취소 뒤 `counts` 는
`queued 0 · cancelled 284 · running 1 · done 12` — 수행중 1건이 남는 것이
의도한 결과다. 그 한 건은 워커가 스스로 끝낸다.

## 배운 것

**안전장치는 반대 방향의 요구를 만든다.** 002 에서 "재시작해도 큐를 잃지 않게"
만들었더니, "그만두고 싶다" 를 막는 벽이 됐다. 유실을 막는 기능을 넣을 때는
**그것을 의도적으로 버리는 길**도 같이 만들어야 한다. 안 그러면 사용자는
디렉터리를 손으로 지우는 쪽으로 간다 — 우리가 제일 피하고 싶은 방법이다.

**되돌릴 수 없는 동작은 범위가 눈에 보여야 한다.** 필터 단위 취소를 버린 이유가
이거다. 버튼이 멈추는 대상이 화면 상태에 따라 달라지면, 누르는 사람은 자기가
무엇을 멈추는지 모른 채 누른다.

**목록과 큐는 다른 것이다.** 카드 목록을 아무리 잘 만들어도 "지금 큐가 어떤
모양인가" 는 안 보인다. 한 건을 보는 화면과 전체를 보는 화면은 따로 필요하다.
