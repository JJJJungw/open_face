# 021 — 파일 이름이 코드였다

파일 이름은 우리가 만드는 값이 아니다. 버킷에 있는 것을 그대로 받아 그린다.
그런데 그 값을 **JS 문자열 안에** 끼워 넣고 있었다.

```js
onchange="toggle('${o.key}', this.checked)"
<span class="nm" title="${o.key}">${name}</span>
```

이스케이프가 없다. 즉 **이름이 곧 코드다.**

## 먼저 밟히는 건 보안이 아니다

`KBS 뉴스 O'Brien 인터뷰.mp4` 같은 정상적인 이름이 들어오면 생성되는 코드가
이렇게 된다.

```js
onchange="toggle('KBS 뉴스 O'Brien 인터뷰.mp4', this.checked)"
```

구문이 깨진다. 체크박스는 눌리는데 `S3.selected` 에 안 들어가고, 목록도 다시
안 그려진다. 화면에는 **체크 표시가 보이는데 "선택된 항목 없음" 이 그대로 있고,
"비식별화 시작" 버튼은 계속 비활성이다.** 사용자가 이유를 알아낼 방법이 없다.

큰따옴표가 들어가면 `title="${o.key}"` 속성이 끊겨 그다음 글자들이 속성으로
해석된다.

방송 자료 파일 이름에 아포스트로피나 따옴표가 들어가는 것은 이상한 일이 아니다.
인터뷰 대상 이름, 인용된 발언 제목이 그대로 파일명이 되는 경우가 흔하다.

## 그리고 이스케이프 함수는 작은따옴표를 몰랐다

```js
function esc(s) {
  return String(s).replace(/[&<>"]/g, ...)   // ' 가 없다
}
```

`esc()` 를 쓴 자리조차 `onclick="f('...')"` 안에서는 뚫린다. 실제로 폴더 칩이
그 상태였다 — 텍스트는 `esc(n)` 인데 속성 안은 `'${n}'` 이었다.

보안 쪽은 그 연장선이다. 버킷에 쓸 수 있는 사람이 이름을
`<img src=x onerror=...>.mp4` 로 지으면 운영자 브라우저에서 실행된다. 우리 API 에
인증이 없으므로 거기서 제출·삭제·저장소 해제가 전부 된다. 다만 버킷 쓰기 권한이
전제라, **정상적인 이름 때문에 기능이 깨지는 쪽이 훨씬 자주 밟힌다.**

## 한 일

**이름을 코드가 아니라 데이터로 넘긴다.**

```js
<input type="checkbox" data-pick="${esc(o.key)}">
```

`data-*` 는 브라우저가 **속성 값으로만** 다룬다. 이름이 무엇이든 HTML 문법에
영향을 못 준다. 클릭은 컨테이너 하나에서 이벤트 위임으로 받는다.

버킷에서 값이 흘러드는 네 경로를 전부 바꿨다 — 파일 브라우저(`renderBrowser`),
빵부스러기(`crumbs`), 진척률 폴더 목록(`renderProgress`), 로그의 폴더
칩(`loadLogBatches`). 그리고 `esc()` 에 `'` 를 추가했다.

**둘 다 해야 한다.** 이스케이프만 고치면 인라인 핸들러가 남아 다음에 누가 하나
더 추가할 때 같은 구멍이 다시 생기고, 위임만 하면 텍스트로 찍는 자리가 남는다.

## 안 바꾼 것

인라인 핸들러가 열 군데 남아 있다. 전부 **우리가 만든 식별자**다 — 작업
id(16진수), 제공자 id, 컬럼 키. 버킷과 무관하고, 바꾸려면 카드·로그·설정 화면을
다 건드려야 하는데 그쪽은 UI 테스트가 없어 되돌릴 근거 없이 만지는 것이 된다.

대신 **규칙을 테스트로 못 박았다.** 버킷에서 값이 오는 네 함수에는 인라인
핸들러를 두지 않는다. 그 목록에 함수를 추가하는 것은 한 줄이다.

## 어떻게 확인했나

UI 테스트가 하나도 없던 폴더라 `tests/test_webui.py` 를 새로 만들었다.

- `esc()` 를 node 로 **실제로 실행해서** 다섯 글자가 다 바뀌는지 본다.
- 적대적인 이름으로 행을 만들어 **HTML 파서에 먹인다.** 태그가 `input`·`span`
  둘뿐이고 속성이 `data-pick`·`type`·`title` 뿐인지 확인한다. 문자열에서
  `onmouseover=` 를 찾는 식으로는 안 된다 — 그 글자는 파일 이름의 일부로
  들어 있는 게 정상이고, 문제는 그게 **실제 속성이 되는 것**이다. 처음에
  문자열로 찾았다가 오탐이 나서 파서로 바꿨다.
- 네 렌더 함수의 본문을 떼어 인라인 핸들러가 없는지 본다.

되돌려서 확인했다. `esc()` 에서 `'` 를 빼거나 브라우저 행을 인라인 핸들러로
되돌리면 해당 테스트가 실패한다.

## 못 한 것

처음에는 "이스케이프 없이 찍는 값" 을 정규식으로 찾아내는 테스트도 넣었는데,
값의 **출처**를 정규식으로 추측하는 물건이라 오탐만 냈다(`logBatches.includes(n)
? 'on' : ''` 은 CSS 클래스지 이름이 아니다). 걷어냈다. 사람이 판단해야 하는 것을
테스트가 흉내 내면 통과·실패 둘 다 못 믿게 된다.
